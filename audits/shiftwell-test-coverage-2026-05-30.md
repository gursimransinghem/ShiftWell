## Method & caveats

- **Adversarial A/B.** Finder agents (A) enumerated each module's behaviors and flagged untested ones; independent verifier agents (B) — which never saw A's reasoning — re-read the source and grepped the *entire* test tree to confirm or refute each claim. Coverage was judged **cross-file** (a behavior tested by an integration test elsewhere counts) and **mock-aware** (a test that exercises a `__mocks__/` stub does **not** count as covering the real module).
- **Scope.** Deep audit of `src/lib/**`, `src/store/**`, and `supabase/migrations/**`. UI (components/screens/theme) got one lightweight LOW-tier sweep — only logic-bearing UI gaps are listed (styling/animation deliberately excluded). 84 Sonnet workers, ≤8 concurrent.
- **⚠️ Caveat — verifier B refuted 0 of 589 confirmed claims.** Zero refutations *can* indicate rubber-stamping. As a check, 3 HIGH gaps in well-tested modules were hand-verified against source + tests (`classify-shifts.ts:55` evening 12:00–13:59 boundary; `sleep-windows.ts:263` `work-evening` branch; `phase-model.ts:146` negative `cumulativeShiftMinutes`) — **all three are legitimately uncovered**, and B's evidence cited exact test lines, indicating real verification. Still, treat any single gap you act on as *claimed* until you confirm it; this is a prioritization map, not a coverage proof. 14 claims were downgraded to `partial`.
- **No silent truncation.** Every confirmed gap below is its own row. Excluded files and skipped scope are accounted for in the appendices.

**Effort:** S = &lt;1h (one pure-function test) · M = 1–3h (cases/fixtures/mocks) · L = &gt;3h (integration harness, live/local Supabase, heavy setup). **B:** `confirmed` = genuinely untested · `partial` = partially covered · `unverified` = UI sweep, not adversarially checked.
